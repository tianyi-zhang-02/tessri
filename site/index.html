Keep code understandable.

Agents write more of the code; people still stand behind it. Tessri reads the code and its git history and hands the person four answers with their evidence: where to look first, who can look, what the change did to the structure, and what nobody maintains.

How does it work?

One pass over the files and the history, then one view per question.

Tested, not assumed

The order is backtested, and what it cannot see it says it cannot see.

And every page ends with what it cannot see: registries, dynamic loading and consumers outside the repository are invisible to static analysis, so a clean result is never a proof. Missing history says unavailable and why.

In the loop

Every station of a change has its question.

  • tessri scan .the report; --format html writes one offline page with the explorer.
  • tessri integration install --agent claudethe skill (or codex, copilot, mcp); --agent claude-hooks puts it in the agent's loop.
  • tessri integration install --agent reviewthe brief on every pull request; integration remove takes it all out.
